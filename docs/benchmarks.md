# Benchmarking Merlin

Merlin is not benchmarked with one dataset or one ASR number. It is benchmarked as an
**adaptive attacker that finds real, executable vulnerabilities under a fixed budget**.
Every result must state the target, the objective, the budget, the oracle, and what
was verified versus what remains unverified. No score is published that the harness
did not actually earn.

## Recommended benchmark stack

| Track | Use |
| --- | --- |
| Hidden executable Merlin suite | Primary product benchmark. Seed known vulnerabilities and benign controls across browser, API, tools, RAG, auth, sessions, tenants, and stateful workflows. Final cases stay private and rotating. |
| MUZZLE + The Zoo | Best public head-to-head we can run today for adaptive web-agent attacks. Compare Merlin and MUZZLE on identical targets, objectives, and budgets. [USENIX Security 2026](https://www.usenix.org/conference/usenixsecurity26/presentation/syros) |
| AIRTBench | Closest broad benchmark for autonomous red-team agents: 70 black-box AI-security challenges with mechanically verified results. Requires a safe Python/code-execution sandbox that Merlin does not yet have. [AIRTBench](https://arxiv.org/html/2506.14682) |
| RIFT-Bench | Compare Merlin against another dynamic agent-security scanner across runnable agent systems. A good public scanner baseline, but public cases are unsuitable as the hidden final test. [RIFT-Bench](https://aclanthology.org/2026.findings-emnlp.1116/) |
| Jailbreak Foundry | Standardized text-jailbreak comparison against roughly 30 attacks under equal settings. Use HarmBench / JailbreakBench objectives here. [ICML 2026](https://proceedings.mlr.press/v306/fang26y.html) |
| AgentHarm 6-B / AgentDojo | Secondary agent-security regression tracks. They mainly measure whether a target agent can be compromised, not the complete quality of Merlin as a harness. [AgentHarm](https://ukgovernmentbeis.github.io/inspect_evals/evals/agentharm/) |
| REDAgentBench / DianJin-RED | Useful as an execution substrate because it verifies final service state, but its stock score measures the vulnerability of the target model and scaffold. We would replace its supplied attacks with attacks generated by Merlin. The dataset is CC BY-NC, so commercial use needs review. [REDAgentBench](https://arxiv.org/html/2608.10669) |

## Track status

### MUZZLE + The Zoo (head-to-head, in progress)

MUZZLE ([github.com/gsiros/muzzle](https://github.com/gsiros/muzzle), USENIX Security 2026)
is an automated, adaptive red-teaming framework for web agents against indirect prompt
injection. Its pipeline is a multi-agent team (Explorer, Summarizer, Grafter, Payload
Generator, Dispatcher, Judge) that discovers injection surfaces and adapts payloads without
human-selected templates, evaluated inside The Zoo
([zoo-eval.github.io](https://zoo-eval.github.io/zoo_website/)), a simulated interconnected
web (email, identity, e-commerce, collaboration, analytics) with deterministic reset.
The official artifact is on Zenodo (record 20399450); The Zoo ships inside the MUZZLE
repository.

Head-to-head contract for this track:

- Same targets: The Zoo applications and seeded scenes.
- Same objectives: the paper's adversarial objectives (confidentiality, availability,
  privacy) under the same budget.
- Same agent scaffolds where practical (Agent-E and Browser-Use are included as submodules).
- Merlin contributes its own attacker (campaign engine with DeepSeek); MUZZLE runs its
  published pipeline with its own LLM provider. Results are compared on objectives achieved
  versus budget consumed, with each system's environment, model, and budget disclosed.

Blockers to solve before running: provisioning The Zoo services (Docker), a provider key for
MUZZLE's LLM roles, and a Merlin target adapter for the Zoo browser flows. No head-to-head
numbers exist yet.

## Current status

The real engine path works end-to-end: a genuine `DurableAgentService` / `CampaignService`
GOAT campaign, with DeepSeek as the provider, drives a reviewed HTTP target that wraps a
local benchmark victim and is scored by the benchmark's own oracle. The drivers are
[`scripts/benchmark_target_server.py`](../scripts/benchmark_target_server.py) and
[`scripts/benchmark_campaign_sweep.py`](../scripts/benchmark_campaign_sweep.py).

Results to date are honest but preliminary:

- One completed real-engine campaign against a HarmBench-style behavior was blocked by the
  aligned victim: the campaign tried two techniques and produced no match. The evidence is
  recorded under `target/benchmark-campaign/`.
- A 20-behavior HarmBench sweep is in progress. The first attempt exposed a driver-side
  campaign-id contract issue (the durable engine derives a tool call's campaign id from the
  first two path segments of the assignment id, so campaign ids must be exactly two
  segments); the driver was fixed and the sweep is re-running.
- No ASR number is published until the sweep completes and the numbers are verified against
  the recorded evidence.

All runs so far are local, non-official reproductions: the victim and judge are local Ollama
models rather than the official benchmark models, and that is disclosed wherever results are
reported.
